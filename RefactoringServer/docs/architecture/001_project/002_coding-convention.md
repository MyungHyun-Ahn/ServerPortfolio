# Coding Convention

## 1. 목적
- 이름만 보고 타입 역할과 소유권 경계를 추측할 수 있게 한다.
- 새 구조에서 작성되는 코드가 한 스타일로 읽히도록 한다.
- 자동 생성된 코드가 아니라, 사람이 유지보수하기 쉬운 형태를 유지한다.

## 2. 접두사 규칙
- `F`
  - 일반 클래스
- `I`
  - 인터페이스
- `S`
  - 구조체와 설정 데이터
- `E`
  - enum
- `T`
  - 템플릿 타입

## 3. 이름 규칙
- 타입, 함수, enum 값은 `PascalCase`
- 지역 변수와 매개변수는 `camelCase`
- 멤버 변수는 `m_` 접두사 사용
- 상수는 `kPascalCase`

## 4. 파일 규칙
- 타입 이름과 파일 이름을 맞춘다.
- 구현이 큰 클래스는 `Include/`와 `Source/`로 분리한다.
- 실험 코드와 검증용 코드는 별도 테스트 프로젝트에 둔다.
- `docs/plans`, `docs/architecture`, `docs/reviews` 아래 새 디렉터리와 새 문서는 `001_`, `002_` 같은 숫자 prefix를 기본 규칙으로 사용한다.

## 5. 설계 규칙
- 상위 계층은 구현체보다 인터페이스에 의존한다.
- 전역 상태는 만들지 않는다.
- lock-free 코어에서는 공유 상태를 최소화하고, 결과 판단은 `try-pop`, `try-dequeue` 같은 연산 성공 여부로 한다.
- 주석은 한국어로 작성하고, 왜 이런 경계를 두는지와 어떤 위험을 피하는지 설명한다.

## 6. 현재 적용 범위
- `RefactoringServer/` 아래 새 코드 전체에 적용한다.
