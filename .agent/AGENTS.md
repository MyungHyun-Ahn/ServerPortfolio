# AGENTS.md

이 저장소는 `Windows + MSVC 기반 C++ 게임 서버 포트폴리오` 저장소다.
Codex는 작업 전 문서를 우선 확인하고, 새 문서 작성 시 `.agent/.codex/templates/` 템플릿을 참고한다.

## 1. 기본 원칙
- 항상 근거 기반으로 작업한다.
- 확인하지 못한 동작, 성능, 요구사항은 사실처럼 단정하지 않는다.
- 코드, 로그, 문서, 실행 결과처럼 관찰 가능한 근거를 먼저 제시한다.
- 변경은 최소 범위로 수행하고 기존 스타일과 규칙을 우선 따른다.

## 2. 작업 시작 절차
1. 프로젝트 구조를 확인한다.
2. `README`, `docs/`, 기존 설계 문서, 빌드 스크립트, 테스트 코드를 먼저 읽는다.
3. 문서가 부족하면 실제 코드와 빌드 결과를 기준으로 판단한다.
4. 변경 전 작업 가정과 범위를 짧게 정리한다.

## 3. 구현 원칙
- 기존 네이밍, 오류 처리, 로그 패턴을 우선 유지한다.
- 성능 민감 경로에서는 추가 할당, 불필요한 복사, 넓은 잠금 범위를 경계한다.
- 동시성 코드에서는 소유권, 수명주기, 경합 조건을 먼저 점검한다.
- 로그는 운영과 디버깅에 필요한 정보만 남긴다.

## 4. 헤더 / PCH 규칙
- `.cpp`는 반드시 각 프로젝트의 `Pch.h`를 먼저 include 한다.
- 헤더 파일에서는 `#include`를 기본값으로 두지 않는다.
- 가능하면 forward declaration을 사용한다.
- 다음 경우만 헤더 include를 허용한다.
  - 기반 클래스 정의가 필요한 경우
  - 값 멤버로 완전형이 필요한 경우
  - 템플릿/inline 구현이 헤더에 있어 완전형이 필요한 경우
  - 공개 헤더라 자립성이 꼭 필요한 경우
- 변경 빈도가 낮고 반복 사용되는 STL/Windows 헤더는 `Pch.h`로 올린다.
- 공개 헤더와 내부 구현 헤더를 구분해서 판단한다.

## 5. 주석과 문서
- 코드 설명 주석은 한국어로 작성한다.
- “무엇을 한다”보다 “왜 이렇게 했다”, “어떤 제약이 있다”를 우선 설명한다.
- 구조가 복잡하거나 근거가 필요한 변경은 문서를 함께 만든다.

## 6. 검증 원칙
- 가능한 범위에서 빌드 또는 테스트를 직접 수행한다.
- 검증하지 못한 항목은 명시적으로 남긴다.
- 성능 결과는 반복 측정과 환경 차이를 고려해 보수적으로 해석한다.

## 7. 응답 원칙
- 무엇을 바꿨는지
- 왜 바꿨는지
- 어떤 근거로 판단했는지
- 무엇을 검증했는지
- 어떤 문서를 추가/갱신했는지
를 짧고 명확하게 정리한다.
